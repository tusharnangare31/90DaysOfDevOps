# Docker Permission Issue

When I tried running:

```bash
docker ps
```

I received a permission denied error.

### Reason

Docker communicates using:

```bash
/var/run/docker.sock
```

Only authorized users can access this socket.

---

# Fixing Docker Permissions

To solve the issue, I added the current user to the Docker group.

Command used:

```bash
sudo usermod -aG docker $USER
```

### Observation

After re-login:
- Docker commands worked without sudo
- Permission issue was resolved successfully

This was an important learning because Linux permissions are critical in DevOps environments.

# Deploying Nginx Container

I deployed an Nginx container using:

```bash
docker run -d -p 80:80 nginx
```

### Understanding the Command

- `-d` → Detached/background mode
- `-p 80:80` → Host-to-container port mapping
- `nginx` → Container image

### Observation

The container started successfully and exposed Nginx on port 80.

This helped me understand:
- Container deployment
- Port exposure
- Background container execution

# Running Logs in Background

Command used:

```bash
nohup docker logs -f <container-id> > nohup.out &
```

### Understanding the Command

- `nohup` → Keep process running after terminal closes
- `> nohup.out` → Save output into file
- `&` → Run in background

### Observation

Log monitoring continued successfully in the background.

This is useful for:
- Long-running monitoring
- Production debugging
- Persistent log collection
